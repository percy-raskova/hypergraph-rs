# The raise to XGI 1.1: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.
> A fresh builder takes one task, a fresh reviewer checks it, then the next task begins.

**Goal:** Make hypergraph-rs mirror XGI 1.1 instead of XGI 0.10.2: XGI 1.1's test suite runs against the library,
every breaking change of XGI 1.x is followed, and the new features XGI 1.1 tests are built.

**Architecture:** First the test importer is rebuilt so that it takes an XGI tag and can no longer let a ported test
reach the real XGI that sits in the same virtual environment. Then the additions that XGI 0.10.2's tests never
touch are built while the gate still runs against 0.10.2. Then one change moves the pin to 1.1, re-imports the
tests and records every test that newly fails as a strict expected failure owned by a named later task. The tasks
after it each remove their own expected failures. The last task writes the release notes and runs every gate.

**Tech Stack:** Rust (toolchain pinned in `rust-toolchain.toml`, floor in `Cargo.toml` `rust-version`), PyO3 and
maturin for the bindings, pytest, numpy and scipy in the gate, XGI 1.1 from PyPI as the test-only oracle.

**Spec:** the owner's rulings of 2026-11-21 and the lead's calls that follow from them, restated in Global
Constraints below; the map of the work (XGI 0.10.2 against 1.1, the library as it stands, the gap list, the order of
work) was read when this plan was written, and every fact a builder needs from it is in the tasks.

## Global Constraints

Every plan for this library carries these:

- The library is public and must stay usable by itself: nothing of any game in its code, tests, docs or examples.
- Everything at its newest version: crates, the pinned toolchain, CI's Python, workflow actions. The minimum Rust
  version rises when a dependency needs it; nothing is held back.
- The gates are the repository's own: `mise run rust:check` (fmt, clippy with warnings denied, tests, rustdoc with
  warnings denied, all features, each feature alone), `mise run rust:msrv`, cargo-deny, CodeQL, and for the Python
  bindings `mise run py:gate`. A task ends with the narrowest of these that covers what it touched; the whole set
  runs once at the end of the plan (Task 21).
- One cargo or pytest process at a time on the machine (`maturin develop` is a cargo process). Never pass `-j` or
  `--jobs`.
- Commits: the repository has no git identity of its own. The lead supplies the author and committer through the
  environment (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`) on every
  commit. A builder never runs `git config` and never commits without that environment. Every commit step below
  starts with `test -n "$GIT_AUTHOR_NAME" -a -n "$GIT_COMMITTER_NAME" || exit 1`.
- No release to crates.io or PyPI. That is the owner's to order.
- The one known user takes the library by git revision with default features off and uses only `Hypergraph` and
  `subhypergraph` (`add_node`, `add_edge` with an explicit id, `remove_edge`, `remove_node`, `members`,
  `memberships`, `edge_attrs`, `edge_ids`, `has_edge`, `copy`, `is_frozen`). No task may break a build with default
  features off, and none of those methods changes its signature or result.

This plan's own:

- Work on the branch `feat/xgi-1-1-raise`, which the lead makes from `origin/main` (pull request 4's merge,
  `4e05b4e6`, or later). Builders never switch branches and never push.
- The oracle is XGI at exactly `1.1` after Task 8 and exactly `0.10.2` before it. The gate refuses any other
  version (`tools/gen_manifest.py` `require_xgi_target`).
- The Python mirror follows every breaking change of XGI 1.x exactly: the `dict` default of `members`,
  `dimembers`, `head` and `tail`; the dict-shaped `repr`; no view methods on the network objects;
  `cleanup(empties=)`; `add_nodes_from` with a dict; the new exception types. It drops everything XGI dropped.
- In Rust, XGI's old JSON format (`readwrite/json.rs`, the `hypergraph_dict` conversions) is removed. The Kuramoto
  code stays behind the `dynamics` feature as the crate's own extra, no longer checked against XGI.
- Rust generator functions take XGI's new names, with no aliases.
- Random generators: the same seed always gives the same result in the library, with the same statistical
  properties as XGI's. The library does not reproduce XGI's very draws. Tests compare the library's generators
  with XGI 1.1 statistically (Tasks 16, 19, 20).
- Attribute values stay JSON (divergence D23): tuples come back as lists. `test_pos_stat` stays a recorded
  difference.
- The release is 0.3.0. XGI is pinned at exactly 1.1, and CONTRIBUTING gains the rule that every XGI release is
  followed by a new conformance pass.
- Three parts the owner ordered are each a later plan of their own and are NOT built here: the online data
  loaders (`load_ahorn_data`, `load_hypergraphx_data`, `request_from_url` and its cached form, certificates
  checked by default), the machinery for user-defined statistics (`nodestat_func` and its five siblings), and
  XGI's documentation examples run as tests. Their tests are recorded with owner `later:online-loaders`,
  `later:stat-functions` and `later:doc-examples`. Drawing with matplotlib and `xgi.skill` stay out of scope.
- `upstream`, below, is XGI's source as the importer fetches it, or the installed oracle in `.venv` (read only,
  never edited, never imported by a ported test). Where a task says "port from XGI", read
  `.venv/lib/python3.*/site-packages/xgi/<file>` after Task 8 has installed 1.1.
- Python commands run as `.venv/bin/python`; the extension is rebuilt with `.venv/bin/maturin develop`. The local
  `.venv` is a uv environment with no pip: install into it with `uv pip install --python .venv/bin/python ...`
  (CI's `.venv` is made by `python -m venv` and keeps `.venv/bin/python -m pip`).
- Every binding a task adds, renames or removes is changed in `python/hypergraph_rs/_hypergraph_rs_core.pyi` in the
  same commit.
- Markdown lines at most 120 columns; plain words.

## Review Focus

1. **A ported test that reaches the real XGI.** A `mock.patch("xgi.…")` string or an import the importer did not
   rewrite would test XGI against itself and pass. Task 1's guard must fail the run, even for a test that is a
   strict expected failure (`test_patch_of_the_oracle_fails_the_session`).
2. **A seed that is ignored.** A generator that ignores its seed, or a numpy `Generator`, passes every
   same-seed-same-result check. Tasks 7, 16, 19 and 20 each assert that two different seeds give different results
   and that a reused `Generator` advances (`test_generator_seed_is_consumed`,
   `test_different_seeds_differ`).
3. **A 2-tuple node id given to `add_nodes_from`.** XGI 1.1 reads `(1, 2)` as node `1` with attributes `2` and
   raises `TypeError`; `(1, None)` is node `1` with no attributes. Task 12 pins both
   (`test_two_tuple_is_node_and_attrs`).
4. **A frozen graph and the new mutators.** `add_weighted_edges_from` and `add_weighted_simplices_from` must refuse
   a frozen graph as `add_edges_from` does. Task 4 pins it (`test_weighted_adds_refuse_a_frozen_graph`).
5. **An empty edge and a positional caller of `cleanup`.** The default now removes empty edges, and `empties` sits
   before `multiedges`, so `H.cleanup(False, False, True)` keeps empty edges. Task 14 pins both
   (`test_cleanup_removes_empty_edges_by_default`, `test_cleanup_positional_empties`).

**Decisions:**
- *Source of the tests:* a clone of XGI in `.cache/xgi` (gitignored), made by `ensure_repo` with
  `git clone XGI_REPO_URL` when absent and `git fetch --tags` otherwise. Files are read with
  `git rev-parse <tag>^{commit}` (must equal `KNOWN_TAGS[tag]`, else `UpstreamImportError`),
  `git ls-tree -r --name-only <tag> tests/` and `git show <tag>:<path>`. Nothing in the clone is ever run.
- *What the tests dir may hold:* `conftest.py` and `test_*.py` files only. Any other file under `tests/` at the
  tag is an `UpstreamImportError` that names it, so a future data directory is noticed, not dropped.
- *`rewrite` rules, the only changes the importer makes:*
  1. a line matching `^(\s*)import xgi\s*$` becomes `\1import hypergraph_rs as xgi`;
  2. a line matching `^(\s*)from xgi(\.|\s)` has `from xgi` replaced by `from hypergraph_rs`;
  3. a string literal token (found with `tokenize`, kind `STRING`) whose value is `xgi` or matches
     `xgi(\.[A-Za-z_][A-Za-z0-9_]*)+` has that leading `xgi` replaced by `hypergraph_rs`, keeping prefix and
     quotes. This covers the 28 `mock.patch` targets of v1.1 such as
     `"xgi.readwrite.hypergraphx_data._download"`.
  Everything else is left alone: `xgi.Hypergraph(...)` call sites (the alias), `"import xgi took 3s"`,
  `load_xgi_data`, comments.
- *`leftovers`* parses with `ast` and reports: an `Import` of `xgi` or `xgi.*` (`import hypergraph_rs as xgi` is
  fine), an `ImportFrom` whose module is `xgi` or starts with `xgi.`, a `str` constant that rule 3 would rewrite,
  and any f-string whose literal text contains `xgi.` (it cannot be rewritten safely). `import_tests` raises
  `UpstreamImportError` listing every leftover of every file before it writes anything.
- *`import_tests` writes:* each upstream test file, rewritten, as bytes; deletes the files the previous lock lists
  that the new tag lacks, and only those (repo-authored files such as `test_property_differential.py` are never
  touched); replaces everything in `tests/conftest.py` up to and including the old sentinel line with
  `rewrite(upstream conftest)` followed by `sentinel_line(xgi_version_of(tag))` and a newline, keeping every byte
  after the old sentinel line (the old line is the one line matching
  `^# === END VERBATIM XGI \S+ conftest — repo-authored code below this line ===$`; none or two is an
  `UpstreamImportError`); writes the lock. With no lock present (the first run) nothing is deleted.
- *The guard is scoped to upstream files* (the paths in the lock). Repo-authored files under `tests/ported` may
  import the oracle on purpose (`test_property_differential.py` does).
- *How the guard works:* `oracle_hidden(where)` removes every `sys.modules` entry named `xgi` or starting with
  `xgi.`, puts a finder at `sys.meta_path[0]` whose `find_spec` appends to `VIOLATIONS` and raises
  `OracleImportError` for those names, and on exit removes the finder and puts the very same module objects back.
  `tests/conftest.py` wraps `pytest_runtest_protocol` (setup, call, teardown) and `pytest_make_collect_report`
  for `pytest.Module` collectors, each with `@pytest.hookimpl(wrapper=True)`, in `oracle_hidden` when the path is
  upstream. The existing `pytest_sessionfinish` also prints every entry of `VIOLATIONS` and sets
  `session.exitstatus = pytest.ExitCode.TESTS_FAILED` when there is one, so a strict expected failure cannot hide
  an oracle import.
- *The oracle-integrity check compares `ported == rewrite(upstream)` byte for byte* for every upstream file the
  installed wheel ships next to the package (as today, `pathlib.Path(xgi.__file__).parent.parent / "tests"`), and
  checks the lock against the wheel: the same set of files, the same sha256 for each and for `conftest.py`, and
  `lock.xgi_version == xgi.__version__`. The two `_normalise_*` functions go; `_upstream_prefix` and
  `_redefined_below_sentinel` stay, with the sentinel taken from `sentinel_line(read_lock().xgi_version)`.
- *The marker `webtest`* is registered in `pyproject.toml` next to `slow`, with the same kind of description.

**Interfaces:**
- Produces, in `core/views.rs`:

```rust

    /// occurrence in this view; ids in a group in insertion order. XGI's `IDView.duplicate_groups`.
    pub fn duplicate_groups(&self) -> Vec<Vec<String>>;
```

- Produces, in Python: `NodeView.duplicate_groups()` and `EdgeView.duplicate_groups()` on `Hypergraph` and
  `SimplicialComplex`, each returning a `list` of views of the same class, one per group.

**Decisions:**
- *Grouping key:* the set of neighbours (a member that repeats counts once), compared as a set, never by a
  `HashMap` iteration order.
- *A filtered view groups the whole network in Python.* XGI 1.1 groups `self._id_dict`, the network's dict, not
  the view's ids, and returns each group in network order. The Python method therefore calls the Rust method on
  the full view (`hg.inner.edges()` / `.nodes()`), whatever view it is called on. The Rust method groups the ids
  of the view it is called on.
- *`duplicates()` keeps its present result.* It is not rebuilt in this task.
- *No `duplicate_groups` on `DiNodeView` / `DiEdgeView`.* XGI 1.1's inherited version builds
  `frozenset(self._id_dict[id])` where each value is the dict `{"in": ..., "out": ...}`, so it groups by the keys
  `{"in", "out"}` and puts every id into one group. The library leaves it out; Task 9 records the absence and
  Task 21 registers it as a divergence.
